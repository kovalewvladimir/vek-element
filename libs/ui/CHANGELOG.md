## 0.2.1 — 2026-08-26

### Новое

- **Анимация перехода между страницами** — View Transitions API (`document.startViewTransition`).

  Анимируется любая навигация: `router.push`, `<router-link>`, кнопки «назад»/«вперёд» в браузере, `navigateToItem`. Оборачивать вызовы не нужно — кит вешает гвард на `beforeResolve`. Браузер снимает страницу «до» и «после» и сам кросс-фейдит их; снимается страница целиком, поэтому контент, меню, теги и хлебные крошки меняются одновременно.

  Гвард стоит именно на `beforeResolve`, а не вокруг `router.push`, потому что пока браузер ждёт обновление DOM внутри перехода, он не рисует вообще ничего — страница замирает картинкой, ховеры и индикаторы загрузки не двигаются (сам браузер обрывает такой переход только через ~4 секунды). К `beforeResolve` чанк страницы уже догружен и гварды отработали, так что сеть внутрь перехода не попадает: всё долгое происходит при живом интерфейсе.

  Для остального DOM — хук `useViewTransition`:

  ```ts
  const { isEnabled, start } = useViewTransition()

  await start(() => (isOpen.value = !isOpen.value))
  ```

  Переходы не накладываются друг на друга. Браузер обрывает анимацию, если начать новый переход поверх играющего, — при быстром листании страниц это видно как рывок. Поэтому вызовы, пришедшие во время анимации, копятся и применяются одним следующим переходом: ни одно обновление не теряется (промежуточные роуты проходятся, теги создаются), но вместо череды промежуточных анимаций проигрывается одна — с той страницы, где переход начался, на последнюю запрошенную.

  Низкоуровневая обёртка доступна в `@vek-element/ui/utils`: `startViewTransition(update)` и `isViewTransitionSupported()`. В браузерах без поддержки API `update` просто выполняется без анимации. Есть страховка: `update`, не уложившийся в 500ms, отменяет анимацию, чтобы зависший переход не заморозил интерфейс.

  Выключение: `createUI({ layout: { viewTransition: false } })` или в рантайме `useLayoutConfigStore().viewTransition.setEnabled(false)`.

  Длительность всех частей перехода — css переменная `--view-transition-duration` (по умолчанию `150ms`); при `prefers-reduced-motion: reduce` переход мгновенный.

- **Индикатор загрузки страницы** — `TheNavigationProgress`, тонкая полоса сверху layout.

  Появляется, если навигация идёт дольше 200ms: обычный переход в это укладывается, и полоса не мигает почём зря, а вот догрузка чанка страницы или запрос в гварде — нет. Уже встроена в `classic-layout`, отдельно подключать не нужно.

  Состояние доступно хуком `useNavigationProgress()` → `{ isNavigating }`, если индикатор хочется нарисовать по-своему.

## 0.2.0 — 2026-08-26

### Новое

- Подпуть **`@vek-element/ui/vite`** — build-time точка входа с фабрикой плагинов `VekElementPlus`.

  ```ts
  import { VekElementPlus } from '@vek-element/ui/vite'

  export default defineConfig({
    plugins: [Vue(), ...VekElementPlus(), UnoCSS()]
  })
  ```

  Фабрика возвращает два плагина:
  1. настроенный `unplugin-element-plus` — с `exclude`, который пропускает через трансформацию пакеты `@vek-element/*` (кит ставится исходниками и стили element-plus сам не импортирует, а дефолтный `exclude` плагина закрывает `node_modules` целиком);
  2. `vek:element-plus-styles` (`apply: 'serve'`) — объявляет `optimizeDeps.include` со списком стилей element-plus, чтобы vite не дособирал пре-бандл при заходе на страницу и не перезагружал вкладку (`optimized dependencies changed. reloading`).

  Список стилей читается обходом каталога `es/components` у element-plus, установленного **в проекте** (у кита он в `peerDependencies`). Если element-plus не найден, чтение конфига не падает: список пустой плюс предупреждение в консоль.

  Опции (обе необязательные): `elementPlus` — сквозная передача опций в `unplugin-element-plus` поверх дефолтов кита; `optimizeStyles` (по умолчанию `true`) — выключатель второго плагина.

### Изменения

- `unplugin-element-plus` переехал в `dependencies` кита — потребителю его больше не нужно ни ставить, ни настраивать в своём `vite.config.ts`.
- Из `vite.config.ts` потребителя убираются импорт `unplugin-element-plus/vite`, его ручная настройка и блок `optimizeDeps` со списком стилей element-plus.
- В `files` пакета добавлен `dist`: подпуть `./vite` поставляется скомпилированным JS (его грузит сам Node при чтении конфига vite, без сборщика). Остальные экспорты (`.`, `./layout`, `./utils`) по-прежнему отдаются исходниками.
